# MCP 接入与模型 API

MCP 可供支持本地 stdio 的 harness 使用。开局页显示实际握手上报的客户端名称，不再绑定 Grok。

## 自动配置与客户端发现

完整重启更新后的游戏。在新游戏中，将文明设为“外部 AI（MCP）”，打开“连接方式”，从客户端列表选择 WorkBuddy 或 Antigravity，点击“配置连接”，再“打开客户端”。客户端列表也提供“重新扫描”。

在客户端里选择模型，首次添加后启用或刷新 CivBench MCP，再新建对话调用 `game_session`。等游戏显示“已连接”再开始；“已配置”不代表已连接。支持的客户端配置只需添加一次，后续对局由游戏更新文明绑定，不重写同一份客户端配置。

共享配置模式下，每份客户端配置绑定一个文明；独立会话模式为每个席位生成独立工作目录和绑定，同一客户端的不同会话可以控制同局的不同文明。请从对应的独立目录启动会话；同一目录中的两个对话不会自动隔离。模型列表由客户端管理，游戏不读取模型账号或密钥。客户端目录覆盖40类本地痕迹，其中15类支持自动配置，其余提供手动接入；发现痕迹不等于模型已连接。详细支持范围、信任要求、备份与检查见 [Local harness connections](HARNESS_CONNECTIONS.md)。

## 连接外部客户端

1. 完整启动更新后的游戏，开始新游戏，使用回合制。
2. 在文明列表中，把对应控制者设为“外部 AI（MCP）”；AI 名称自动映射上报的模型，未上报时显示“待识别”，无需填写。先完成整局的地图、文明和控制者设置。模型 API 的 AI 名称仍自行填写。
3. 点击该文明的连接行或“连接方式”。选择 JSON（mcpServers）或 TOML（mcp_servers），点击“复制 MCP 配置”。
4. 将生成的配置添加到所用 harness 的 MCP 配置中，再启用或刷新该客户端的 MCP 连接。不同 harness 的配置文件位置和导入方式由它自己决定。
5. 回到游戏，确认该文明显示“已连接”。多个 AI 分别复制各自文明的配置；每个配置只包含对应文明的凭证。
6. 需要观战时勾选“只读观战”，然后“开启纪元”。保留人类文明时，仍需完成自己的回合。

列表中的名称来自 MCP initialize 的客户端自报信息；这不是厂商身份或实际模型身份的认证，也不是扫描电脑里的所有 harness。未上报名称的连接仍保留基本连接状态。心跳断开后最多约 45 秒更新状态。

修改已准备的地图、文明或控制者配置会使先前连接失效，需要重新连接。不要把同一文明的凭证分给多个同时操作的客户端。

## 直接接模型 API

将控制者设为“模型 API”，点击对应文明的连接行，填写接口地址、模型名和密钥；检查连接后点击“接入 API 玩家”。多个模型各自配置。普通兼容接口使用 Chat Completions；支持 Responses 的服务也可选择该协议。

API 玩家持续行动到终局、被淘汰、执行错误或你在局内停止。开局没有试玩回合目标。局内可停止、继续或修改 API 设置。外部 MCP 的“停止 AI”会阻止后续游戏命令，不会关闭整个 harness。

密钥仅保留在主机内存，不写入存档、浏览器持久存储或生成的 MCP 配置。关闭主机后需要重新填写。连接检查会发送实际 API 请求。

## 更新和保存

MCP 1.3 可返回 `observation_ref` / `next_observation_ref` 短引用。把它作为写工具的 `observation_token` 参数值即可，完整长令牌仍然可用。短引用绑定具体观察，过期时仍须重新观察；适配器重连后也要重新获取。不要把短引用理解成“自动使用最新状态”。

这几项适配器改进重连游戏 MCP 即可加载，无须为了它们重开正在进行的对局。下文涉及后台路由的更新仍需要完整启动相应的新后台。

长局开始或重连后先调用 `game_session`，再读取 `game_observe` 摘要并查看前面的重要待办。未轮到自己时用 `game_events(wait_ms=30000)` 等待，并把返回的 `next` 用作下一次 `cursor`。一次等待超时不是终局。客户端任务结束后，MCP 连接仍可能保持，不能据此断言模型在后台继续玩。

`game_options` 使用 `city` / `unit` 或 `cities` / `units` 筛选，未知字段会报错。遇到令牌格式错误或 `unknown_observation_reference`，不带旧令牌重新观察，再使用新返回的短引用；不要反复提交同一个错误值或让主机代跳回合。

这版增加了客户端身份心跳和持续 API 模式，需要下次正常完整启动加载后台。仍在运行的旧后台会提示新接入功能尚未加载；只刷新页面不能升级后台。不要为了更新而丢弃尚需保留的独立对局。

独立 MCP 对局沿用现有保存边界，不写正式自动存档。修改前先确认需要保留的当前对局；不能假定关闭独立主机会自动恢复它。
